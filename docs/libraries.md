# Library compatibility matrix

**This is not an allowlist.** Any library with a podspec is tried automatically: Expo modules come through Expo's SwiftPM
plugin, React Native libraries that ship a `Package.swift` link directly, and CocoaPods-only libraries get a
`Package.swift` generated by React Native's `spm scaffold` (with the generic fixes rn-xtool patches in). A library that
nobody has tested should still build when its iOS code is ordinary Swift / Objective-C. A CocoaPods pod a library
depends on is linked through its SwiftPM package when rn-xtool's pod table, or the `pods` of your
`rn-xtool.config.json`, names one ([details](troubleshooting.md#libraries-that-depend-on-cocoapods-pods)). A pod that
ships prebuilt static binaries is read from the CocoaPods CDN, downloaded, checked against the project's
`rn-xtool-pods.lock.json` and linked; only ML Kit text recognition is verified (on a physical iPhone, on React Native
0.88.1), and it makes the app about 53 MB larger. Those files are the vendor's: ML Kit's are Google's, under the ML
Kit Terms (https://developers.google.com/ml-kit/terms). rn-xtool downloads them for your own build and does not accept
the terms on your behalf ([details](troubleshooting.md#cocoapods-binaries)). What does not work yet, on any library: a
library's own vendored `.xcframework` binaries (`binaryTarget`), pods from a git source without a SwiftPM package, other
shapes of binary pods (dynamic frameworks, Swift binaries), and anything that needs Xcode's tools (asset catalogs,
storyboards, Metal shaders). A scaffolded library's `resource_bundles` reach the app as `<name>.bundle` when their names
and globs are plain strings; its plain `resources`, and bundles written as Ruby code, do not, and `build` names them in
one `ℹ Not copied into the app` line ([details](troubleshooting.md#scaffolded-libraries)). If a library fails, please
open an issue with the "My library does not build" template and the output of `rn-xtool doctor --report`
([details](troubleshooting.md#reporting-a-problem)); that is how this table grows.

The table lists what has been checked by hand on a physical iPhone.

Each library is tested on the reference app (`expo-ios-linux/app`, Expo SDK 58 / RN 0.88) on its own
`feature/lib-<name>` branch: `npx expo install <lib>` → smoke usage in `App.tsx` → `rn-xtool run` →
checked by hand on a physical iPhone. Dates are the test dates.

precompiled xcframework, RN library with its own Package.swift, or CocoaPods-only (→ Package.swift generated automatically by `spm scaffold` and persisted in the
project's `patches/`).

Scaffolded libraries' `resource_bundles` are built by rn-xtool, not as SwiftPM resources (SwiftPM would name the bundle
`<package>_<target>.bundle`, not the name the code looks up): each becomes `<name>.bundle` at the root of `App.app`,
as CocoaPods places it, which also gives react-native-svg its Metal filters
