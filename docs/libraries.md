# Library compatibility matrix

**This is not an allowlist.** Any library with a podspec is tried automatically: Expo modules come through Expo's SwiftPM
plugin, React Native libraries that ship a `Package.swift` link directly, and CocoaPods-only libraries get a
`Package.swift` generated by React Native's `spm scaffold` (with the generic fixes rn-xtool patches in). A library that
nobody has tested should still build when its iOS code is ordinary Swift / Objective-C. What does not work yet, on any
library: podspec `resource_bundles` (the library's own resources), vendored `.xcframework` binaries (`binaryTarget`),
and anything that needs Xcode's tools (asset catalogs, storyboards, Metal shaders). If a library fails, please open an
issue with its name and version; that is how this table grows.

The table lists what has been checked by hand on a physical iPhone.

Each library is tested on the reference app (`expo-ios-linux/app`, Expo SDK 58 / RN 0.88) on its own
`feature/lib-<name>` branch: `npx expo install <lib>` → smoke usage in `App.tsx` → `rn-xtool run` →
checked by hand on a physical iPhone. Dates are the test dates.

The `Bare 0.88` column is the same library on a bare React Native 0.88 app (`@react-native-community/cli init`, no Expo; checked on a physical iPhone, 2026-10-26). `Bare 0.87.1` and `Bare 0.86.3` are the same on bare apps of those versions (vendored SwiftPM scripts), checked the same way on 2026-10-27. Libraries marked ⏳ in a Bare column are untested there, not known to fail.
Bare apps need `plugins: ['react-native-worklets/plugin']` in their own `babel.config.js` for reanimated/worklets (`babel-preset-expo` adds it for Expo apps), and the same two reanimated/worklets patches as the Expo reference app, copied into the project's `patches/`.

"Linkage seen" records how the library reached the SwiftPM graph: Expo source package, Expo
precompiled xcframework, RN library with its own Package.swift, or CocoaPods-only (→ Package.swift generated automatically by `spm scaffold` and persisted in the
project's `patches/`).

Next generic scaffolder fix: `resource_bundles` support (read `s.resource_bundles` / `s.ios.resource_bundles` and emit the
bundle as a SwiftPM resource), which would also enable react-native-svg's Metal filters.
