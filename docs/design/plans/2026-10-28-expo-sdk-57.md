# Expo SDK 57 through a Vendored Expo SwiftPM Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `rn-xtool doctor | build | install | start | run` work on `create-expo-app --template blank-typescript@sdk-57` projects (expo 57.0.31, react-native 0.86.3), with Expo 58 and bare 0.86.2/0.86.3/0.87.1/0.88.0 unchanged except for the listed generic fixes. Tasks 18–22 (spec amendment "SDK 58 version drift") then move Expo 58 to the 58.0.21 set as a floor, add bare 0.88.1, and add the G4 precompiled-symbol check.

**Architecture:** An Expo version table says, per SDK, whether the project's own Expo SwiftPM plugin (58+) or a vendored copy of `expo@58.0.19` `scripts/spm` (shared patch plus vendored-only edits P1–P5) drives the build. SDK 57 runs on the bare driver path (`rn-spm-generate.js`, vendored RN scripts, the adapted 0.86.3 artifacts) with the vendored plugin, autolinking 58.0.15 and expo-modules-macros 0.22.0 as rn-xtool dependencies, and SDK 57's own precompiled ExpoModulesCore. A JSI step, moved before `rn-spm`, builds ExpoModulesJSI and synthesises the `ExpoModulesJSIHeaders.xcframework` SDK 57 does not ship.

**Tech Stack:** TypeScript (Node 20, ESM), vitest, CommonJS driver `scripts/rn-spm-generate.js`, vendored RN 0.88.0 scripts (`vendor/rn-spm`), vendored Expo 58.0.19 plugin (`vendor/expo-spm`, MIT 650 Industries), expo-modules-autolinking 58.0.15, expo-modules-macros 0.22.0, `plist`, xtool 1.23.0, Swift 6.4.

**Spec:** `docs/design/specs/2026-10-27-expo-sdk-57-design.md` (amendments at its end are binding; evidence: `docs/research/expo-57-vendored-plugin-spike.md`, `docs/research/compat-suite-proposal.md`, `docs/research/expo-58-drift.md` for Tasks 18–22; spike artefacts read-only under `<scratch>/spike57/`: `vendored-edits.diff`, `rnx-dist.diff`, `Spike57/.spike/`).

## Review Focus

1. An SDK 57 project where npm nests expo-modules-core, expo-modules-jsi or expo-modules-autolinking under another package must be gated on the copy the build resolves (core from `expo`, jsi from core), not on a hoisted stray (Task 2 test `reads each pin where the build resolves it`); and since patch-package patches only the top-level copy, a jsi the build resolves from anywhere else is refused (Task 2 test `refuses a nested expo-modules-jsi`).
2. ExpoModulesJSI rebuilt with a changed interface but the same jsi version (patch re-applied, Swift upgrade) must rewrite the headers xcframework; an interrupted synthesis must leave nothing the next build treats as current (Task 5 tests `rewrites when the interface changes` and `a failed synthesis leaves no stamped xcframework`).
3. A global install: the vendored plugin must load the app's `@expo/config-plugins` and `xcode`, not rn-xtool's 58 copies next to it (Task 1 test `P2 resolves app packages from RN_XTOOL_PROJECT_ROOT, never from vendor/`).
4. An SDK 57 project whose `rnArtifactsDir` points at raw, unadapted 0.86.3 slots must stop at `jsi` naming the missing headers directory, not fail deep inside `swift build` (Task 5 test `stops when the React Native headers are missing`).
5. `build --clean` on SDK 57 deletes `ios/` (adapted slot, `expo-precompiled`): the plan must re-run `rn-artifacts` and `jsi` before `rn-spm` (Task 6 test `expo 57 --clean re-creates artifacts and JSI headers before rn-spm`).
6. SDK 58 floor: a newer 58.x package warns and the build continues; a package below the floor, or react-native ≠ 0.88.1, stops. expo-file-system and expo-font are read where expo resolves them (`expo/node_modules` first), not from a hoisted stray (Task 19 tests `warns and continues on a newer 58.x` and `reads expo-file-system and expo-font where expo resolves them`).
7. Bare 0.88.0 and 0.88.1 both stage their own react-native patch; `rnPatchMismatch` fires only when no bundled react-native patch matches the installed version (Task 18 test `flags react-native only when no bundled patch matches`).
8. G4: a precompiled framework that imports a symbol its provider does not export stops the build in `frameworks`, before anything is staged; weak imports and libraries outside the embedded set never count (Task 20 tests `finds the ../app crash pair`, `ignores weak imports and system libraries`, build.test `checks symbols before staging`).
9. G2 on SDK 58 tells the user to remove the jsi pin, never to add one (Task 19 test `refuses a nested expo-modules-jsi on SDK 58`).
10. Before the final verdict the reviewer answers, hint-free: "Name three ways this fails in production that no test covers." Any answer not in the spec's failure table goes to Willy as a decision, not to the implementer as a fix.
