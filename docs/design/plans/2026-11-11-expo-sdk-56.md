# Expo SDK 56 Implementation Plan

**Goal:** `rn-xtool doctor | build | install | start | run` work on Expo SDK 56 projects (expo 56.x from 56.0.24,
react-native exactly 0.85.3), proved on a fresh `default@sdk-56` template built from zero, on the owner's device pass
and on the owner's SDK 56 app, with Expo SDK 57, Expo SDK 58 and bare 0.85 unchanged except for the generic fixes
listed. The row merges only after the owner's device pass.

**Architecture:** SDK 56 runs on SDK 57's path: the vendored Expo 58.0.19 plugin, the vendored React Native 0.88.0
scripts, the adapted 0.85.3 artifacts of the bare 0.85 line, the `jsi` step before `rn-spm`, and the precompiled modules
that ship in the npm packages (ExpoModulesCore, ExpoModulesWorklets, ExpoFileSystem, ExpoFont, ExpoImage and its
`spm-deps`). The line is one `SUPPORTED_LINES` row, which the gate, `doctor`, the overrides remedy and the drift watch
already read. Four generic changes close the spike's four gaps: a bundled jsi 56 patch, the JSI headers found in either
layout, a readable ExpoModulesJSI interface behind a guard, and vendored edit P7 (each Expo package at its podspec's
iOS floor). No code path branches on the SDK number.

**Tech Stack:** TypeScript (Node 22.12+, ESM), vitest, `tsc --noEmit` as lint, the vendored Expo plugin (`vendor/expo-spm`,
CommonJS, MIT 650 Industries), the vendored RN scripts (`vendor/rn-spm`), patch-package, xtool 1.24.0, Swift 6.4 with the
Darwin SDK (investigation and proof only), `llvm-nm` (G4).

**Spec:** `docs/design/specs/2026-11-11-expo-sdk-56-design.md` (approved 2026-11-11). The owner confirmed its
failure-walk rulings of rows 1–40; rows 41–46 await the owner's confirmation. This plan carries each row's owner below.

## Review Focus

1. **Where npm puts expo-file-system and expo-font.** SDK 56 hoists them; a lockfile can nest one under `expo` next to
   a top-level copy of another version. The gate must read the copy autolinking links, as autolinking's own CLI
   answers (Task 1 tests `reads expo-file-system and expo-font where autolinking links them on SDK 56`, `gates the %s
   copy the app lists on SDK 56` and the group `reads the expo-font copy autolinking's own CLI links`; rows 41 and 44).
2. **A jsi newer than 56.0.14.** It must get 56.0.14's patch, never 57.1.3's, and a patch failure must name the SDK 56
   overrides (Task 2 tests `never stages another SDK's patch on SDK 56` and `names the SDK 56 overrides when its jsi
   patch fails on a newer 56.x`).
3. **A jsi package in either header layout**, including one whose `NativeState.h` includes a header that is not there
   (Task 3 tests `writes jsi 56's layout: NativeState.h from include/ with its local includes` and `names a local
   include that is not next to NativeState.h`).
4. **An interface with an unreadable line the fix does not know**, from a newer jsi or Swift 6.4.x: it must stop at
   `jsi` by name, never reach `xtool-build` (Task 4 test `stops on a broken line it does not know`).
5. **Podspec platform forms** beyond the template's: one line or several, `s.ios.deployment_target`,
   `s.platform = :ios, '…'`, a `test_spec`'s own platforms, a variable (Task 5 test `P7 reads the iOS deployment
   target a podspec declares`).
6. Before the final verdict, the reviewer answers without hints: "Name three ways this fails in production that no
   test covers." Any answer not in the failure-walk table goes to the owner as a decision, not to the implementer as a
   fix.
